# PaperNest 写作评测集

`writing_eval_set.json` 是 P5 的固定、可复现主题集。它用于在相同检索输入和证据约束下比较单 Agent、串行流水线与多 Agent 协作，避免每次运行因主题变化而产生不可比结果。

## 数据契约

顶层对象包含 `schema_version`、`name`、`description`、`topics` 和 `sources`。每个主题包含稳定的 `id`、检索 `query`、标题和两个章节；章节使用稳定的 `id` 与顺序 `no`，并列出写作要点 `points`、金标准主张 `claims` 以及允许使用的 `source_keys`。

每条主张至少包含 `claim_id`、`text`、`source_key` 和 `quote`，数字型主张可提供 `numbers` 数组。`claim_id` 和 `source_key` 都是评测集内稳定标识，不依赖数据库自增的 paper id。`quote` 必须逐字出现在对应来源的 `abstract` 中；加载器应在运行前执行这一包含校验，并拒绝不匹配的样本。

`source` 记录 `source_key`、本地数据库中的 `norm_key`、题名、摘要、年份和作者。当前样本没有可用的 `pages` 行，因此没有虚构页码；摘要证据仍可进行逐字机械核验。

## 覆盖范围

- **智能体评测框架与事实核验**：包含 AgentGym 的 7/14/89 覆盖数字，以及静态事实核验评测“难以自动评估理由生成”的不足证据。
- **临床预测与工程自动化**：包含 CARE-AD 的 0.53、0.26–0.45 和 10 年窗口，以及 AutoCFD 的 28716、21、88.7% 和 82.6% 数字。
- **智能体方法与网页导航**：提供无数字的综述分类和网页导航挑战主张，用于检测引用覆盖而不依赖数字匹配。
- **近场 XL-MIMO 估计与限制**：包含 MBPD 方法证据，并保留“并非所有情况下都优于 MBPD”的明确边界，检验不足与冲突审计。

## 评测协议

每个系统都接收同一主题 `query`、章节 `points` 和来源候选。输出应按章节保存草稿、引用和运行指标。评测至少记录以下指标：

1. **证据覆盖率**：生成的事实性主张中，能绑定到对应 `claim_id` 且通过 quote 逐字核验的比例。
2. **引用准确率**：文中引用的 `source_key` 是否属于该章节白名单，并与主张绑定来源一致。
3. **数字保真度**：`numbers` 中每个数字在草稿和其绑定 quote 中是否一致；报告缺失、改写和冲突。
4. **不足证据保留率**：带有限定语的金标准主张（例如 `While not consistently better ...`）是否被保留，不能把局部优势扩写成无条件结论。
5. **重写次数、延迟和成本**：记录协调器重试/局部修复次数、端到端耗时以及模型调用 token 或费用；失败章节单独计数，不从整体平均中隐去。

建议以 `claim_id` 为最小对齐单位计算 precision、recall 和 F1，并同时输出每个主题及每个章节的分项值。聚合时使用宏平均，保留原始分母和失败状态，以便审计。

## 来源与复现

数据从 `data/papernest.db` 只读抽取，并与仓库根目录现有 `eval_set.json` 的 DOI 规范键交叉核对。摘要在写入前执行了逐字包含断言；任何来源摘要更新后都应重新生成该文件并更新数据版本。评测运行不得修改真实数据库，临时结果写入独立报告文件。

运行命令为 `python cli.py writing-eval`。默认是离线基线，不访问网络或模型；加 `--online` 才启用真实模型。在线模式未配置模型时，主题会记录为失败项，不会冒充离线模板结果。`--limit 1` 可先做冒烟运行，`--out` 指定报告文件。
